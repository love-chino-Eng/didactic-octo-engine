## 4.1 总体方案与工作流程

系统由“上位机串口 + PS 应用程序 + PL 计时逻辑 + 板载按键/指示灯”四部分组成，单局流程如下：

1. PS 打印操作说明并倒计时 5 s；
2. **预启动**：向 CH1 写 start=1、stim=0，计时器清零并进入 armed，LED 全灭，此阶段进入抢跑监视循环（每 10 ms 轮询一次 btn_pressed）；
3. **随机延时**：由 xorshift 伪随机数发生器产生 1000～5000 ms 的等待时间与目标灯编号（0～3）；
4. **点灯并启动计时**：一条 AXI 写操作同时置位 stim_led 与 start，使 LED 点亮与计数器清零发生在同一时刻；
5. **等待按键**：轮询 CH2，命中后读取 axi_gpio_time 的 32 位计时值与 btn_index；
6. **判决与计分**：按键编号与目标灯一致则换算为毫秒并计分，否则判“按错”；5 s 内无按键判超时；
7. 重复 3 轮，最后输出命中数、超时数、抢跑数、总得分与平均反应时间。

## 4.2 PL 端 reaction_timer 模块设计

该模块是全部实时逻辑的载体，采用参数化设计：`CLK_FREQ_HZ`（默认 100 MHz）、`DEBOUNCE_MS`（默认 20 ms）、`DEBOUNCE_EN`（置 0 可旁路片内消抖，用于按键已由外部消抖的场合）。消抖所需计数值由参数自动换算（100 MHz × 20 ms = 2 000 000，需 21 位计数器）。端口定义见表 3。

表 3  reaction_timer 端口定义

| 方向 | 信号 | 位宽 | 说明 |
| --- | --- | --- | --- |
| 输入 | clk / rst_n | 1 / 1 | 100 MHz 系统时钟；异步低有效复位 |
| 输入 | btn_in | 4 | 板载按键，异步、高有效 |
| 输入 | start | 1 | 上升沿有效：计数器清零并重新使能 |
| 输入 | stim_led | 4 | 目标灯 one-hot 码，计时期间透传到 led_out |
| 输出 | led_out | 4 | 等待期显示目标灯，命中后锁定为命中键 |
| 输出 | timer_value | 32 | 反应时间，单位为一个时钟周期 |
| 输出 | btn_index | 2 | 命中按键编号 0～3 |
| 输出 | btn_pressed | 1 | 命中标志，保持到下一次 start |
| 输出 | armed / press_pulse | 1 / 1 | 计时中状态 / 单周期脉冲（可接 PS 中断） |

模块内部包含四个功能块：4 路并行的“两级同步 + 计数消抖”单元（每路约 23 个触发器，合计不足 100 个，资源开销可忽略）、消抖后按键的上升沿检测与优先级编码、start 上升沿检测（避免 start 长时间为高导致重复清零）、以及主状态机（空闲/FROZEN 与 armed 两态）。命中时 `timer_value` 锁存的是按下前一拍的计数值，因此量化误差为 ±1 个时钟周期（±10 ns）。

## 4.3 Block Design 与中断配置

在 Vivado 中新建 Block Design，加入 ZYNQ7 Processing System 并运行 Block Automation，主要配置为：

- **UART1** 使能，映射 MIO48/49，波特率 115200（Zybo Z7 板载 Micro-USB 串口接的是 UART1，UART0 对应 MIO46/47，不可混用）；
- **DDR3** 控制器使能，按板卡预设参数配置；
- **FCLK_CLK0** 输出 100 MHz，作为 PL 逻辑时钟，同时作为 AXI 互联与两个 GPIO 的时钟；
- 使能 **IRQ_F2P**，将 `btn_pressed`（电平信号，而非 1 个时钟周期的脉冲）接入 GIC，供需要中断方式时使用。

两个 AXI GPIO 均映射到 `M_AXI_GP0`，地址由 Address Editor 自动分配为 0x4120_0000 与 0x4121_0000。CH1 全部配置为输出、CH2 与计时 GPIO 全部配置为输入，因此软件无需写方向寄存器。最后生成 HDL Wrapper、综合实现并导出含比特流的 XSA 文件供 SDK 使用。

## 4.4 引脚与时序约束

PL 侧对外只有 8 个真实引脚（4 键 + 4 灯），引脚分配取自 Digilent 官方 Zybo-Z7-Master.xdc，如表 4 所示。需要说明的是，本设计并不存在“100 MHz 输入时钟引脚”：板上唯一的 125 MHz 晶振（K17）未被使用，PL 时钟来自 PS 内部经时钟网络送入的 FCLK_CLK0，不经过封装引脚，因而无需也无法为其编写引脚约束。

表 4  按键与 LED 引脚约束

| 板卡丝印 | BD 端口 | XDC 端口名 | 封装引脚 | 电平标准 |
| --- | --- | --- | --- | --- |
| BTN0 | btn_in[0] | {btn_in[0]} | K18 | LVCMOS33 |
| BTN1 | btn_in[1] | {btn_in[1]} | P16 | LVCMOS33 |
| BTN2 | btn_in[2] | {btn_in[2]} | K19 | LVCMOS33 |
| BTN3 | btn_in[3] | {btn_in[3]} | Y16 | LVCMOS33 |
| LD0 | led_out[0] | {led_out[0]} | M14 | LVCMOS33 |
| LD1 | led_out[1] | {led_out[1]} | M15 | LVCMOS33 |
| LD2 | led_out[2] | {led_out[2]} | G14 | LVCMOS33 |
| LD3 | led_out[3] | {led_out[3]} | D18 | LVCMOS33 |

编写约束时须注意 `get_ports {btn_in[0]}` 中的花括号不可省略，否则 Tcl 会把方括号当作命令替换而报错；端口名必须使用 Wrapper 顶层的端口名（`btn_in`/`led_out`），写成板卡丝印 `BTN0` 会匹配不到端口，最终导致比特流生成时因存在未约束 I/O 而失败。DDR3 与 UART 的 MIO 引脚属于 PS 专用引脚，由硬核直连，不需写入 XDC。

## 4.5 PS 端软件设计

裸机程序不使用 BSP 的驱动库，而是直接读写寄存器，主要考虑是减少中间层、便于定位问题。程序结构如下：

- **时钟与缓存初始化**：清除 SCTLR 寄存器的 C 位关闭 D-Cache。Zynq 启动代码会打开 MMU 与 D-Cache，若存储器映射外设区被当作可缓存区域，对 UART、GPIO 的写操作会滞留在 Cache 中而无法到达硬件，表现为“程序在运行但串口一个字节都不输出”；
- **UART 初始化**：写 CR=0（关闭收发）、MR=0x20（8 位无校验 1 停止位）、BAUDGEN=124、BAUDDIV=6（100 MHz/(124+1)/6 = 115200），最后写 CR=0x10C 使能收发；
- **字符输出**：轮询 channel_sts 的 TX FIFO 满标志后写 TX FIFO，自行实现整数与定点小数（毫秒保留 3 位）打印；
- **随机数**：32 位 xorshift，种子由延时循环构造，保证每次上电灯序不同；
- **主循环**：按 4.1 节流程执行，全部判决在 PS 完成，硬件只负责计时与锁存。

## 4.6 关键工程问题及处理

调试过程中遇到的主要问题与处理办法汇总于表 5。其中第 1 条是导致“程序下载成功但串口始终无输出”的根本原因：下载完成后立即回读 DDR，发现首条指令由 0xEA000049 变为 0xAA000049，出现单比特翻转，说明本环境下 DDR 数据通路不可靠，CPU 取指即触发异常并跳入未初始化的异常向量区，UART 自然从未被初始化。将应用程序链接到片内 OCM（192 KB）后问题彻底消失。

表 5  调试中的主要问题与对策

| 序号 | 现象 | 原因分析 | 处理办法 |
| --- | --- | --- | --- |
| 1 | 下载成功但串口无任何输出，PC 停在异常向量区 | 程序位于 DDR，取指时数据发生位翻转，执行非法指令 | 修改链接脚本，将代码/数据段放到 OCM（起始 0x0，长度 0x30000），入口变为 0x00000000 |
| 2 | UART 控制寄存器 CR 始终为 0x114，TXEN 未置位 | 程序未运行到初始化代码 | 与第 1 条同源，改用 OCM 后解决 |
| 3 | 早期版本调用 BSP 库函数后死循环 | 库函数在本环境触发异常 | 改为直接读写寄存器，不依赖 BSP 驱动 |
| 4 | 复位后下载报 MMU 翻译错误 / DDR 写失败 | 复位时序不完整，PS 未执行 ps7_init | 启动脚本按“系统复位→ps7_init→配置 PL→核复位→下载→运行”的顺序执行 |
| 5 | 调试时 JTAG 报 DAP status f0000021 | 程序运行中读取外设寄存器导致调试端口锁死 | 不在运行态读寄存器；必要时断电重启 |
| 6 | 统计信息出现异常大数 | 计数器变量位于栈上被破坏 | 将统计变量改为静态变量，固定在数据段 |

完整的构建与部署流程为：Vivado 执行构建脚本生成工程、Block Design 与比特流 → 导出 XSA → SDK 建立应用工程并编译 → 通过 xsdb 脚本完成“ps7_init → 下载比特流 → 下载 ELF → 运行”，串口终端观察输出。
